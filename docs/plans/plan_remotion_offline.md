# remotion の描画で外への通信を止める — #1594（その 1）

## 目的

remotion の場面（Claude が書いたコード、またはホストが渡したコード）を描くブラウザから、外への通信を出させない。場面が使ってよいのは、その描画のために手元で立てたバンドルのサーバーだけ。常に有効にする（設定は無い）。

## 方法（試し測りで確かめた組み合わせ）

| 経路                                                                                     | 止め方                                                                                                                                                          |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HTTP(S) の要求（`fetch`、XHR、`<img>`、CSS `url()`、ワーカーからの `fetch`、ページ移動） | ブラウザ全体で CDP の `Fetch.enable` を有効にし、許可しない URL は `Fetch.failRequest`                                                                          |
| `WebSocket`、`EventSource`                                                               | バンドルの `index.html` に CSP `connect-src 'self' data: blob:` を入れる（`Fetch` はこれを捕まえない）                                                          |
| WebRTC（STUN の UDP）                                                                    | 全てのページとフレームで、読み込み前に `RTCPeerConnection` などを消す（CDP の自動接続 + `Page.addScriptToEvaluateOnNewDocument`）。CSP は WebRTC を対象にしない |

許可する URL: その描画のバンドルのサーバー（`localhost` / `127.0.0.1` / `[::1]` の、毎回選ぶ空きポート）と、`data:` / `blob:`。`localhost` の他のポートは通さない。

バンドルのサーバーそのものを踏み台にする道も塞ぐ（レビューで見つかった）:

| 道                                                                                                | 止め方                                                 |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `/proxy?src=…`（Node 側が `src` を取りに行く）                                                    | `/proxy` で始まるパスは止める                          |
| CSP の無いページ（一覧ページ、404）を iframe や `window.open` で開き、その中の `WebSocket` を使う | ページとして読み込めるのは `/` と `/index.html` だけ   |
| `<Audio>` / `<Video>` の `src` を、描画中に Node 側がダウンロードする                             | `onDownload` で `data:` 以外を止める（描画は失敗する） |

## 変更

- `src/utils/remotion/network_policy.ts`（純粋な関数）: 許可する URL の判定、CSP の文字列と `index.html` への差し込み
- `src/utils/remotion/render.ts`: `openBrowser` で 1 回の描画につき 1 つブラウザを開き、通信を止めてから `puppeteerInstance` と `port` を各呼び出しに渡す。終わったら閉じる
- 止めた URL はログに出す

## 確かめること

- 単体テスト: 許可の判定（ポート違い、別ホスト、IP、`file:`、`ws:` など）、CSP の差し込み（`<head>` が無ければ失敗）
- 実際の描画: 全ての経路を試す場面を描き、手元の待ち受け（別ポートの TCP と UDP）に何も届かないこと、描画が成功すること。ガードを外した対照では届くこと（手順と結果は PR に記録）
